# OzonTech E-CUP 2026: аудит экспериментов и handoff

## 1. Задача

Нужно предсказать GMV каждого пользователя на следующие 30 дней.

- Метрика: RMSLE, меньше — лучше.
- Размер каждого временного среза: 250 000 пользователей.
- Target: сумма `gmv` за дни `cutoff + 1 ... cutoff + 30` включительно.
- Признаки строятся только по событиям `event_date <= cutoff`.
- Текущий лучший leaderboard score: **1.6555566434897157**.
- До первого места, по оценке команды, не хватает примерно **0.01 RMSLE**.

## 2. Временные срезы

Используются expanding-window train/validation и шесть размеченных срезов:

| Название | Cutoff | Период target |
|---|---:|---:|
| August | 2025-08-17 | 2025-08-18 — 2025-09-16 |
| September | 2025-09-16 | 2025-09-17 — 2025-10-16 |
| October | 2025-10-16 | 2025-10-17 — 2025-11-15 |
| November | 2025-11-15 | 2025-11-16 — 2025-12-15 |
| December | 2025-12-15 | 2025-12-16 — 2026-01-14 |
| January | 2026-01-14 | 2026-01-15 — 2026-02-13 |

Competition cutoff: `2026-02-13`, скрытый target соответствует периоду `2026-02-14 — 2026-03-15`.

Основная rolling validation:

```text
Aug + Sep                 -> Oct
Aug + Sep + Oct           -> Nov
Aug + Sep + Oct + Nov     -> Dec
Aug + Sep + Oct + Nov + Dec -> Jan
```

## 3. Текущий лучший подход

Лучший submission получен ансамблем CatBoost, LightGBM и Simple GRU в log-пространстве.

Веса:

```text
CatBoost: 0.6749685343
LightGBM: 0.1894350329
Simple GRU: 0.1355964328
```

Формула:

```python
prediction_log = (
    0.6749685343 * catboost_prediction_log
    + 0.1894350329 * lgbm_prediction_log
    + 0.1355964328 * gru_prediction_log
)

prediction = np.expm1(prediction_log)
```

Результаты:

| Модель/ансамбль | Leaderboard RMSLE |
|---|---:|
| CatBoost + LightGBM | 1.656651 |
| CatBoost + GRU | 1.655916 |
| CatBoost + LightGBM + GRU | **1.6555566435** |
| Blend 2 | 1.6556577036 |

Главный подтверждённый вывод: полезным оказалось не дальнейшее улучшение одного бустинга, а объединение моделей с различающимися ошибками. GRU полезна прежде всего как источник diversity.

Контрольный файл:

```text
ensemble/submissions/submission_catboost_lgbm_gru.csv
```

Его нужно сохранять как неизменяемый benchmark.

## 4. Базовые модели и отбор признаков

Для исходных 629 классических признаков на декабрьской validation получены:

| Эксперимент | Validation RMSLE |
|---|---:|
| CatBoost, все 629 признаков | 1.741073 |
| LightGBM | 1.741956 |
| CatBoost, top-500 признаков | 1.741080 |

Выводы:

- CatBoost сильнее одиночного LightGBM.
- Отбор top-500 по CatBoost importance не дал улучшения: разница с полным набором находится на уровне шума.
- Простое удаление слабых по importance признаков не является перспективным источником `0.01`.

Базовые параметры CatBoost:

```python
CatBoostRegressor(
    loss_function="RMSE",
    eval_metric="RMSE",
    iterations=3000,
    learning_rate=0.03,
    depth=8,
    l2_leaf_reg=5,
    random_strength=0.5,
    random_seed=42,
    thread_count=-1,
    allow_writing_files=False,
)
```

Модель обучается на `np.log1p(target)`, отрицательные log-предсказания обрезаются до нуля, затем применяется `np.expm1`.

## 7. Признаки покупательского цикла

К исходным 629 модельным признакам было добавлено 48 новых признаков. Новый feature set содержит 677 модельных признаков.

Добавленные группы:

### 7.1. Интервалы между заказами

- `order_gap_q25_270d`
- `order_gap_q75_270d`
- `order_gap_q90_270d`
- `order_gap_iqr_270d`
- `order_gap_q90_to_median_270d`
- `order_last_gap_to_median_270d`
- `order_last_gap_to_mean_270d`

### 7.2. Персональная фаза покупательского цикла

- `order_overdue_ratio_270d`
- `order_days_to_expected_270d`
- `order_overdue_days_270d`
- `order_expected_within_30d_270d`
- `order_cycle_phase_270d`
- `expected_orders_next_30d_270d`
- `expected_orders_next_30d_with_overdue_270d`

### 7.3. Последние покупочные дни

- GMV последних 1/2/3 покупочных дней;
- количество купленных товаров в последних 1/2/3 покупочных днях;
- отношение последнего GMV к среднему двух предыдущих;
- тренд последнего GMV относительно двух предыдущих.

### 7.4. Активность после последнего заказа

- searches после последнего заказа;
- добавления в корзину после последнего заказа;
- число search/cart/active days после последнего заказа;
- интенсивность searches/cart на день после последнего заказа;
- доля активных дней после заказа;
- бинарные признаки наличия нового поискового или корзинного намерения.

### 7.5. Фазы месяца

Заказы разбиты на интервалы:

```text
1–7
8–15
16–23
24–конец месяца
```

Для каждой фазы рассчитаны число покупочных дней, GMV и их доли.

### 7.6. Rolling validation cycle-признаков

Baseline, 629 признаков:

| Fold | RMSLE |
|---|---:|
| Fold 1 | 1.6993012621 |
| Fold 2 | 1.7353574526 |
| Fold 3 | 1.7419403468 |
| Fold 4 | 1.6885430146 |
| Mean | **1.7162855190** |

Cycle, 677 признаков, первые три фолда с early stopping и Fold 4 до 5000 деревьев:

| Fold | RMSLE | Улучшение |
|---|---:|---:|
| Fold 1 | 1.6992497969 | 0.0000515 |
| Fold 2 | 1.7352996459 | 0.0000578 |
| Fold 3 | 1.7416293528 | 0.0003110 |
| Fold 4 | 1.6385951332 | 0.0499479 |
| Mean | **1.7036934822** | **0.0125920** |

Fold 4 продолжал улучшаться вплоть до ограничения в 5000 итераций:

```text
3000: 1.660351
3500: 1.654820
4000: 1.649305
4500: 1.643954
4999: 1.638595
```

Это выглядело как достаточный прирост для отправки, но leaderboard показал:

```text
submission_catboost_cycle_5000.csv: 1.6584779166
```

Относительно лучшего ансамбля ухудшение составило:

```text
1.6584779166 - 1.6555566435 = 0.0029212731
```

Ключевой вывод: почти весь validation gain пришёл из единственного последнего фолда. На первых трёх фолдах улучшение было практически нулевым. Вероятнее всего, новые признаки выучили январский сезонный режим или shortcut, который не перенёсся на февральско-мартовский competition target.

Прямой временной утечки в генераторе признаков не найдено: все новые признаки используют history только до cutoff.

Текущий набор cycle-признаков целиком применять не следует. Если возвращаться к нему, нужна ablation по четырём независимым группам:

1. cadence/gaps;
2. последние заказы;
3. активность после последнего заказа;
4. фазы месяца.

Принимать группу только при улучшении минимум 3 из 4 фолдов или при доказанной полезной diversity для ансамбля.

## 11. Что улучшило процесс, но не метрику напрямую

- Построены согласованные августовский–январский classic snapshots.
- Добавлена expanding-window validation по всем доступным cutoff.
- В `train_model.py` добавлено клонирование модели для каждого fold.
- Исправлена поддержка `sample_weight` по файлам.
- Добавлен режим финального обучения без target в competition test.
- Зафиксирована проверка схемы файлов и правильного порядка cutoff.
- Submission всегда сохраняется с колонками `user_id,predict`.

Это важные инженерные улучшения: они уменьшают вероятность ошибочного submission и дают более честную оценку экспериментов.

## 12. Главные ошибки экспериментального процесса

### 12.1. Доверие среднему, вытянутому одним фолдом

Cycle mean улучшился на `0.01259`, но почти весь gain пришёл из Fold 4. Медианный gain и число улучшившихся фолдов показали бы, что эффект неустойчив.

### 12.2. Подбор на одном временном периоде

Optuna, калибровка и некоторые blend-веса выбирались преимущественно на одном cutoff. При сильной сезонности это создаёт переоптимизацию.

### 12.3. Не для всех экспериментов сохранены OOF predictions

Без OOF невозможно измерить:

- корреляцию ошибок;
- вклад модели в ансамбль;
- качество по сегментам пользователей;
- оптимальный blend без использования leaderboard.

### 12.4. Многократное использование leaderboard

Различия порядка `0.0001–0.0005` после большого числа отправок нельзя уверенно считать реальным улучшением.

## 13. Правило приёмки будущих экспериментов

Новая модель или группа признаков принимается, если выполнено хотя бы одно условие:

1. Улучшает минимум 3 из 4 временных фолдов и улучшает mean/median RMSLE.
2. Не улучшает standalone RMSLE, но имеет достаточно отличающиеся OOF-ошибки и улучшает OOF-ансамбль.

Минимальный отчёт каждого запуска должен содержать:

```text
RMSLE каждого fold
mean RMSLE
median RMSLE
worst-fold RMSLE
best iteration каждого fold
OOF predictions
корреляции OOF predictions с текущими моделями
результат blend на OOF
```

Нельзя принимать эксперимент только из-за большого улучшения одного последнего fold.

## 14. Что уже не стоит продолжать

- длинный tuning текущего CatBoost в том же пространстве;
- текущий полный набор cycle-признаков;
- текущая реализация Tweedie;
- прямой BTYD;
- текущая two-stage схема;
- stacking в проверенном виде;
- бесконечный подбор весов уже существующих CatBoost/LightGBM/GRU;
- feature selection только по CatBoost importance.

## 15. Что ещё не закрыто и выглядит перспективно

### Приоритет 1: TCN/1D CNN

Использовать существующие дневные sequence-срезы, но заменить рекуррентную обработку на dilated temporal convolutions. Такая модель может находить локальные 7/14/30-дневные паттерны и давать ошибки, отличающиеся и от GRU, и от boosting.

### Приоритет 2: TabM

Обучить TabM на 629 базовых classic features, не добавляя сразу нестабильные cycle-признаки. Даже модель немного слабее CatBoost может быть полезной для ансамбля при низкой корреляции ошибок.

### Приоритет 3: ablation cycle-групп

Не использовать все 48 признаков одновременно. Проверить четыре группы по отдельности на всех fold и сохранить OOF.

### Приоритет 4: новый LightGBM pipeline

- собственная LightGBM importance;
- собственный top-k;
- tuning `num_leaves`, `min_child_samples`, `feature_fraction`, `lambda_l1/l2`;
- OOF predictions на всех временных fold.

### Приоритет 5: hurdle-модель с корректным OOF

Если возвращаться к two-stage:

1. classifier для `target > 0`;
2. regressor только для положительного target;
3. подбор формулы объединения только на OOF всех cutoff;
4. сравнение по сегментам zero/non-zero и recency.

Предыдущая реализация two-stage с leaderboard `1.701314` считается неудачной, поэтому нужна новая постановка, а не настройка старой.

## 16. Вопросы для следующей модели

Нужно изучить весь репозиторий и предложить идеи, которые могут дать не косметический gain `0.0001–0.001`, а приблизить решение к улучшению около `0.01`.

Особенно важно ответить:

1. Почему ансамбль разных архитектур переносится лучше, чем tuning одного CatBoost?

3. Как построить единый OOF-протокол для CatBoost, LightGBM, GRU и новых моделей?
4. Какие группы текущих 677 признаков наиболее вероятно создают январский seasonal shortcut?

## 18. Итог одним абзацем

Лучший подтверждённый результат `1.6555566435` получен log-ансамблем CatBoost, LightGBM и GRU. CatBoost tuning, top-k selection, веса свежести, дополнительные даты и полный набор cycle-признаков не дали нового leaderboard-уровня. Cycle-признаки создали сильный, но ложный январский validation gain, который не перенёсся на competition. Следующий шанс на значимый прирост связан не с дополнительными деревьями текущего CatBoost, а с новой архитектурой и контролируемым OOF-ансамблированием.
