# Описание датасета

Файл: `train.parquet`

Датасет содержит обезличенную ежедневную активность пользователей в Поиске и Каталоге.

## Общая информация

- Количество строк: 30 631 006
- Количество столбцов: 18
- Количество пользователей: 250 000
- Период данных: с 2025-01-01 по 2026-02-13
- Количество календарных дат: 409
- Одна строка соответствует одному активному дню пользователя
- Пара `user_id + event_date` уникальна
- Пропущенных значений нет
- Данные отсортированы по `user_id`, затем по `event_date`

Датасет разреженный: строки за дни без активности пользователя отсутствуют.

## Столбцы

| Столбец | Описание |
|---|---|
| `event_date` | Дата активности пользователя |
| `user_id` | Идентификатор пользователя |
| `search` | Флаг использования Поиска: 0 или 1 |
| `cat` | Флаг использования Каталога: 0 или 1 |
| `has_search_to_cart` | Флаг добавления товара в корзину при использовании Поиска: 0 или 1 |
| `has_search_to_ord` | Флаг покупки товара при использовании Поиска: 0 или 1 |
| `has_cat_to_cart` | Флаг добавления товара в корзину при использовании Каталога: 0 или 1 |
| `has_cat_to_ord` | Флаг покупки товара при использовании Каталога: 0 или 1 |
| `search_to_cart` | Число товаров, добавленных в корзину при использовании Поиска |
| `search_to_ord` | Число товаров, купленных при использовании Поиска |
| `cat_to_cart` | Число товаров, добавленных в корзину при использовании Каталога |
| `cat_to_ord` | Число товаров, купленных при использовании Каталога |
| `gmv_search` | Суммарная стоимость товаров, купленных при использовании Поиска |
| `gmv_cat` | Суммарная стоимость товаров, купленных при использовании Каталога |
| `to_cart` | Общее число товаров, добавленных в корзину |
| `to_ord` | Общее число купленных товаров |
| `gmv` | Общая стоимость купленных товаров |
| `searches` | Общее число поисковых запросов |

## Связи между столбцами

```text
to_cart = search_to_cart + cat_to_cart
to_ord  = search_to_ord  + cat_to_ord
gmv     = gmv_search     + gmv_cat
```

`to_ord` обозначает количество купленных товаров, а не количество отдельных заказов.

## Временные срезы

Одна строка производного датасета соответствует состоянию одного пользователя на определённую дату `cutoff`.

Признаки рассчитываются только по данным до `cutoff` включительно. `target` — суммарный GMV пользователя за следующие 30 календарных дней.

| Файл | Cutoff | Период target |
|---|---|---|
| `train_1.parquet` | 2025-10-16 | 2025-10-17 — 2025-11-15 |
| `train_2.parquet` | 2025-11-15 | 2025-11-16 — 2025-12-15 |
| `train_3.parquet` | 2025-12-15 | 2025-12-16 — 2026-01-14 |
| `validation.parquet` | 2026-01-14 | 2026-01-15 — 2026-02-13 |
| `competition_test.parquet` | 2026-02-13 | 2026-02-14 — 2026-03-15 |

Целевые периоды обучающих срезов не пересекаются. В `competition_test.parquet` столбца `target` нет, поскольку значения за этот период скрыты организаторами.

История одного пользователя частично повторяется между соседними срезами, но состояние пользователя и его будущий 30-дневный GMV в каждом срезе отличаются.

## Структура производных датасетов

Каждый производный файл содержит по одной строке на пользователя:

```text
user_id | cutoff_date | признаки истории | target
```

Столбцы:

- `user_id` — технический идентификатор пользователя;
- `cutoff_date` — последний день истории, доступный при построении признаков;
- агрегированные признаки за разные временные окна;
- `target` — GMV следующих 30 дней, кроме финального тестового среза.

## Временные окна признаков

Признаки рассчитываются за следующие интервалы до `cutoff` включительно:

```text
7, 14, 30, 60, 90 и 180 дней
```

Например, для `cutoff = 2026-01-14`:

```text
окно 7 дней:  2026-01-08 — 2026-01-14
окно 30 дней: 2025-12-16 — 2026-01-14
окно 90 дней: 2025-10-17 — 2026-01-14
target:        2026-01-15 — 2026-02-13
```

## Агрегированные признаки

Для каждого окна создаются следующие признаки, где `{N}` — длина окна:

| Признак | Описание |
|---|---|
| `gmv_{N}d` | Суммарный GMV |
| `gmv_search_{N}d` | Суммарный GMV из Поиска |
| `gmv_cat_{N}d` | Суммарный GMV из Каталога |
| `items_bought_{N}d` | Число купленных товаров |
| `items_added_to_cart_{N}d` | Число товаров, добавленных в корзину |
| `searches_{N}d` | Число поисковых запросов |
| `active_days_{N}d` | Число дней с записью об активности |
| `gmv_per_item_{N}d` | GMV на один купленный товар |
| `items_per_active_day_{N}d` | Число купленных товаров на активный день |
| `search_gmv_share_{N}d` | Доля общего GMV, полученная из Поиска |

Если знаменатель производного признака равен нулю, значение признака устанавливается равным нулю.

## Признак динамики GMV

`gmv_trend_30d` сравнивает GMV последних 30 дней с GMV предыдущих 30 дней:

```text
recent_gmv   = gmv_30d
previous_gmv = gmv_60d - gmv_30d

gmv_trend_30d =
    (recent_gmv - previous_gmv)
    / (recent_gmv + previous_gmv + 1)
```

Интерпретация:

- значение больше нуля — GMV пользователя вырос;
- значение около нуля — GMV практически не изменился;
- значение меньше нуля — GMV снизился.
