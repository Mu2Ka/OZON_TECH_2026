# План дальнейших экспериментов

## Цель

Текущий лучший результат на leaderboard — `1.655556`. До первого места не хватает примерно `0.01`. Одним изменением весов ансамбля такой разрыв, скорее всего, не закрыть, поэтому нужно улучшать основные модели и одновременно добавлять новые модели с отличающимися ошибками.

## 1. Январская временная валидация

Сейчас веса ансамбля подбирались на cutoff `2025-12-15`. Январский срез ближе к competition cutoff и лучше отражает последнее распределение данных.

Что сделать:

- обучить CatBoost и LightGBM на срезах до декабря включительно;
- обучить Simple GRU на sequence-срезах до декабря;
- получить предсказания всех моделей на cutoff `2026-01-14`;
- сохранить `user_id`, `target`, обычные и log-предсказания;
- посчитать RMSLE каждой модели и ансамбля.

После этого январь станет основной валидацией, а декабрь — дополнительной проверкой устойчивости.

## 2. Дополнительные classic snapshots

Сейчас бустинг обучается только на октябрьском и ноябрьском срезах. Для нейросети уже используются август и сентябрь, поэтому нужно добавить такие же срезы для классических моделей.

## 3. Новый подбор ансамбля и калибровка

Текущий ансамбль использует фиксированные веса:

```text
CatBoost: 0.67497
LightGBM: 0.18944
GRU:      0.13560
```

Нужно подобрать веса повторно на январе и сравнить их с декабрьскими. Также проверить линейную калибровку итогового log-предсказания:

```python
prediction_log = scale * prediction_log + bias
prediction_log = np.maximum(prediction_log, 0)
```

На декабрьской валидации такая калибровка уже снижала RMSLE примерно с `1.740428` до `1.739211`, но коэффициенты обязательно нужно подтвердить на январе.

Дополнительно проверить:

- смешивание в log-пространстве;
- смешивание обычных предсказаний;
- веса без обязательного условия, что их сумма равна единице;
- отдельные веса для активных и неактивных пользователей.

## 4. TabM

TabM нужно обучать на классическом датасете с агрегированными признаками.

Первый вариант:

```text
Вход: все числовые признаки без user_id, cutoff_date и target
Target: log1p(target)
Batch size: 512–1024
Optimizer: AdamW
Learning rate: 0.002
Weight decay: 0.0003
Epochs: до 50
Patience: 7–10
```

Обязательные шаги:

- нормализовать признаки по статистикам только train-части;
- обучать по временным срезам;
- усреднять внутренние предсказания TabM;
- сохранить предсказания на декабре и январе;
- проверить TabM отдельно и в ансамбле.

Даже если TabM немного хуже CatBoost, он может улучшить ансамбль за счёт других ошибок.

## 5. 1D CNN или TCN

CNN нужно обучать на том же Dataset, который используется для GRU:

```text
batch × 180 дней × количество признаков
```

Перед `Conv1d` необходимо переставить измерения:

```python
x = x.transpose(1, 2)
```

Начальная архитектура:

- `Conv1d` с `kernel_size=7`;
- несколько residual-блоков;
- dilation `1`, `2`, `4`;
- global average pooling;
- global max pooling;
- dropout;
- линейный выход.

CNN должна обучаться быстрее GRU и может лучше находить локальные всплески активности за последние 7, 14 и 30 дней.

## 6. CatBoost с категориальным user_id

Во всех срезах и в competition присутствуют одни и те же пользователи. Поэтому можно проверить `user_id` как категориальный признак CatBoost.

```python
data["user_id"] = data["user_id"].astype(str)
```

Модель должна обучаться с:

```python
cat_features=["user_id"]
```

Эксперимент обязательно оценивать на временной январской валидации. Если использовать случайное разделение строк, можно получить слишком оптимистичный результат.

## 7. Двухэтапная модель для нулевого target

Примерно у 45% пользователей `target = 0`. Можно разделить задачу на две части:

1. CatBoostClassifier предсказывает вероятность `target > 0`.
2. CatBoostRegressor предсказывает `log1p(target)` только для положительных пользователей.

Итоговое предсказание:

```python
prediction_log = probability_positive ** alpha * positive_prediction_log
```

Проверить:

```text
alpha = 0.50
alpha = 0.75
alpha = 1.00
alpha = 1.25
alpha = 1.50
```

Затем сравнить двухэтапную модель с обычным CatBoost и добавить её в ансамбль.

## 8. Отдельный подбор LightGBM

Сейчас финальный LightGBM использует признаки, выбранные по importance CatBoost. Для LightGBM нужно сделать собственный отбор.

Проверить:

- все признаки;
- top-300 по LightGBM importance;
- top-500 по LightGBM importance;
- текущие top-500 CatBoost.

Основные параметры:

```text
num_leaves: 31, 63, 127
min_child_samples: 50, 100, 200, 500
colsample_bytree: 0.6, 0.8, 1.0
reg_lambda: 1, 5, 10
```

Также нужно исправить путь к feature importance: сейчас файл сохраняется как `boosting/hren.csv`, а в другой ячейке может читаться как `../hren.csv`.

## 10. Сегментированный ансамбль

Можно использовать разные веса для пользователей в зависимости от давности последнего заказа:

```text

```

На декабрьской валидации такой подход снижал RMSLE примерно с `1.740428` до `1.739006`, но результат нужно подтвердить на январе.
